# Added: multi-repo model download with switchable .env sets

Halogen was relying on a single `HALOGEN_DOWNLOAD` repo. Quat3rnion publishes
only the abliterated trunk(s); the required n-gram table, tokenizer and
optional vision tower still live on peonist-ai. Wiping `./models` therefore
could not restore a working stack from compose alone.

Ported the flash-next pattern:

- `model-download` one-shot service (`profiles: [init]`) that reads
  `HF_DOWNLOAD_SPECS` (`repo|revision|artifact`, multi-repo, flat into
  `./models`)
- `.env.example` with four switchable sets (Quat3rnion v2 / HT43 abliterated,
  peonist stock v2 / HT43)
- `./dc.sh` for init, download, up, restart, logs
- serve settings (`HALOGEN_CHECKPOINT`, vision, model id, download flag)
  moved into `.env` so switching sets is comment-one-block

After a wipe: `./dc.sh download && ./dc.sh up`. NPU models still auto-fetch
on first start when `HALOGEN_DOWNLOAD` is set.

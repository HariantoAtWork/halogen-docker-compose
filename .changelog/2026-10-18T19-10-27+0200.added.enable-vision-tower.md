# Added: enable the vision tower so Halogen accepts images

Halogen was serving text only even though `models/qwen38-flash-next-vision.hgn`
(0.84 GiB) already sits in the models volume. The entrypoint only loads the
vision sidecar when `HALOGEN_VISION_TOWER` is set; with it unset it prints
"a vision sidecar is present but NOT loaded" and keeps the endpoint text-only.

Set `HALOGEN_VISION_TOWER: /models/qwen38-flash-next-vision.hgn` in
`docker-compose.yml` so the running server picks up the tower beside the
abliterated checkpoint. `all` mode is a supported mode for the tower, so no
other change is needed.

Cost notes for reference:

- the tower adds about 0.84 GiB to the engine's memory budget; the host still
  has roughly 79 GiB available, so the existing KV sizing stays valid
- an image costs about 1,000 tokens at 1280x800 and about 2,040 at 1080p
- `HALOGEN_VISION_MAX_PIXELS` caps the input (default 2560x1440, larger
  images are downscaled)

`docker-compose.override.yml` is untouched, so the tsdproxy routing on
`halogen` stays as configured.
